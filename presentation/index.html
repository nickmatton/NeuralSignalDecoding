Decoding Motor Intent from Neural Signals

Comparing MLP · 2D CNN · LSTM · Transformer for brain-computer interface decoding

Nick Matton  ·  BME 517, University of Michigan

PyTorch95-ch motor cortex spikesmulti-seed sweep on Lambda GPU

The problem

Given neural activity from 95 motor-cortex channels, predict the hand kinematics the subject is producing:

  • X / Y position
  • X / Y velocity

This is the core decoding step in an intracortical brain-computer interface (BCI) — turning spikes into intended movement.

Metric: Pearson correlation r between predicted and actual kinematics on a held-out test set, per channel, averaged.

Why hard: spike counts are noisy, sparse, and high-dimensional; the mapping to smooth kinematics is nonlinear and temporal.

Dataset & setup

  • contdata95.mat — 31,413 time bins @ 50 ms (~26 min of recording)
  • Inputs: 95 channels of integer spike counts (0–21 per bin)
  • Targets: 4 kinematic variables (X/Y position, X/Y velocity)
  • Temporal split 70 / 15 / 15 — never shuffle across time (avoids leakage)
  • Z-score normalization using train statistics only
  • Sequence models see a 32-bin (1.6 s) window of context

Spike counts — not ECoG voltages. (Fixing that mislabel was one of the bugs below.)

Four architectures

MLP

Single 50 ms bin → 5-layer fully-connected net. No temporal context. Fast baseline.

2D CNN

Treats the 32×95 (time×channel) window as an image; 4 conv blocks + global pool.

LSTM

Recurrent over the 32-bin sequence; final hidden state → kinematics.

Transformer

Encoder-only self-attention over 32 steps, + sinusoidal positional encoding, mean-pooled.

Shared training: Adam, MSE loss, ReduceLROnPlateau, early stopping (patience 15), weight decay on weights only.

I started by auditing the code

Before trusting any number, I reviewed the training pipeline. Found 8 issues across correctness, reproducibility, and honesty:

Crash / non-reproducible: plots written to a non-existent ../../demos/ path — script died before saving results.
Modeling bug: Transformer had no positional encoding → permutation-invariant; couldn't use time order.
No seeding: committed numbers couldn't be reproduced.
Fabricated demo: web demo faked predictions from the answer; "neural" data derived from the trajectory.
Mislabeled data: integer spike counts called "ECoG voltages."
Misnamed model: a pure MLP called "CNN."
Regularization: weight decay applied to BatchNorm/bias params.
Broken demo asset paths → result plots 404'd.

… then fixed them, surgically

Corrected output paths → results/; deterministic set_seed() across Python/NumPy/Torch.
Added sinusoidal positional encoding to the Transformer; even head count.
Excluded BatchNorm/bias from weight decay (standard practice).
Rewrote the demo to load real exported predictions on real held-out spike data — nothing synthetic.
Fixed terminology (spike counts) and model naming (MLP).
Promoted single runs to a multi-seed sweep → mean ± std.

Every changed line traces to a specific finding — no opportunistic refactoring.

Reproducible results: multi-seed sweep

  • The original 2D CNN took ~8 h on CPU / ~90 min on local GPU (MPS) — convolutions over ~22k windows dominate.
  • Provisioned a Lambda Cloud A10 GPU and ran 5 seeds × 4 models = 20 trainings.
  • Report mean ± std instead of a single lucky run — directly addresses the reproducibility gap.
  • Guest agent installed for live GPU/VRAM metrics; instance terminated once results were pulled.

The point: rigorous numbers (mean ± std), not heroic single runs.

Reading the numbers honestly

  • The LSTM's very high r is partly genuine and partly a property of the data:
    • Position targets are slowly varying / highly autocorrelated — easy to track once velocity is decoded.
    • Stride-1 windows make adjacent samples near-duplicates, inflating within-split correlation.
  • I verified the train/val/test split has no target leakage across the temporal boundary.
  • Next steps I'd take: trial-structured CV, report R² and RMSE alongside r, and a velocity-only baseline.

Knowing why a metric looks good is as important as the metric.

Takeaways

  • Temporal context wins: sequence models (LSTM) decode best; a single bin (MLP) is a surprisingly strong, cheap baseline.
  • Positional encoding matters: it's what makes the Transformer able to use time at all.
  • Engineering rigor first: audit, seed, reproduce, and don't ship fabricated demos.
  • Scale when it pays: a GPU was justified for the sweep, not for a single tiny run.
